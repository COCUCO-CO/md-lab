## Errors found & fixes

- **`routes/manual.py` F821 (live bug, pre-existing)**: `save_record` referenced `_record_path` without importing it → NameError → 500 on `POST /api/manual/<step>/record` (called from `frontend/js/manual.js`). Fixed by adding `_record_path` to the `gui.backend.manual` import.
- **SyntaxError in `routes/manual.py::attempt_complete`** introduced mid-edit: non-default `body: dict` after default `system_id = Query(None)`. Fixed by giving `body` a default.
- **`UnknownSystem` crash for DRAFT systems** in `step_status.py`: `_f3_done`/`_f8_status`/`_f9_status` called `systems.construction_dir(system_id)` for systems with `replicas/` but no `system.json`. Fixed by catching `UnknownSystem` and treating construction-dependent status as not-done/blocked/ready per previous-step state.
- **Visual suite hang (pre-existing infra bug)**: first full visual run was 19 failed / 19 passed in 588 s; server main thread stuck in `pipe_write`. Root cause: `tests/visual/conftest.py` piped uvicorn stdout without draining it. Fixed with a daemon drain thread. After the fix: 38 passed in ~23.5 s. GPU saturation by unrelated VLLM workers was investigated and ruled out (`--disable-gpu` did not change the outcome).
- **`routes/approvals.py` 422 on natural requests (live bug, found in post-implementation review)**: `segment0_approval_status` / `f14_extend_approval_status` declared the path parameter as `gate_replica` while the route path is `/{replica}`; FastAPI therefore treated `gate_replica` as a required *query* parameter and `GET /api/approvals/segment0/rep01` returned 422. Fixed by renaming the parameter to `replica` in both handlers.
- **`backend/approvals.py::get_latest_approval` ignored the `gate` argument (safety bug, found in post-implementation review)**: the loop reassigned `gate = rec.get("gate", "")` before validating, so every record was checked against its *own* gate and the requested gate was never filtered. A valid `F11_segment0` approval therefore satisfied `check_f14_extend_approval` (and the `/api/approvals/f14/{replica}` endpoint), which could have let an F14 extension launch on the strength of an F11 approval. Fixed by skipping records whose `gate` differs from the requested one; added regression test `test_approval_gate_is_filtered` (F11 record present → F14 check returns `(False, None)` and the endpoint reports `approved: false`).
- **Grep gate vs spec docstring conflict**: spec §2.1's suggested `systems.py` docstring contained the literal "risperidone", but the §2.5 Verify block greps for zero hits of that literal in `backend/`. The grep gate takes precedence; docstring rephrased to "never fall back to a hardcoded ligand name".
- **Ruff baseline invalid across versions**: the pre-G4.1 baseline (933 errors) was measured with ruff 0.2.1; current ruff is 0.11.0 (938 pre-existing). Per-rule deltas are therefore not comparable; the operative check is "new files clean + no new errors from the diff", both satisfied.
